## 2024-05-18 - Prevent Buffer Overflows with Path Variables
**Vulnerability:** Several places in the code used `strcpy()` and `strcat()` to copy user-supplied paths or dynamically constructed strings into fixed-size buffers, particularly those representing paths (e.g., `MAX_PATH` sized arrays). An example was found in `src/steam.c`, where user-controlled program paths were copied directly into a `MAX_PATH` buffer without bounds checking. Other instances were found in `src/tools/dynacache.c`.
**Learning:** Fixed-size buffers are common for path storage in C. However, blindly using `strcpy()` and `strcat()` with these buffers risks a buffer overflow if the source string length is unexpectedly long or manipulated by an attacker.
**Prevention:** Always use bounds-checking string manipulation functions when dealing with fixed-size arrays. Prefer `strncpy(dest, src, sizeof(dest) - 1); dest[sizeof(dest) - 1] = '\0';` over `strcpy()`. Similarly, prefer `strncat(dest, src, sizeof(dest) - strlen(dest) - 1);` over `strcat()`.
## 2024-05-19 - Replace sprintf with snprintf to prevent buffer overflows
**Vulnerability:** Found multiple instances of `sprintf` being used with fixed-size arrays without proper bounds checking, specifically in `src/libtools/box32_inputevent.c`, `src/libtools/signals.c`, and `src/tools/env.c`. This could lead to buffer overflows if the dynamically formatted string exceeds the buffer size, such as when parsing process IDs or file descriptors into path strings.
**Learning:** `sprintf` is inherently unsafe as it provides no mechanism to restrict the number of characters written, making it a classic vector for buffer overflow vulnerabilities. This risk is amplified when the input being formatted isn't strictly controlled.
**Prevention:** Strictly use `snprintf` instead of `sprintf` throughout the C codebase to guard against buffer overflows and ensure robust defense-in-depth security practices. The `snprintf` function requires the buffer size as an argument and will truncate the output to prevent overflowing the buffer.
